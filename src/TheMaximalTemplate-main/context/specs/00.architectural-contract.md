# Spec 00 — Fix the Architectural Contract

**Priority:** P0  
**Issue intent:** Correct governance and deterministic architecture rules before generating replacement application code.

## Why this exists

The repository currently contains stale instructions that would cause the next coding agent to faithfully recreate known architectural defects.

This spec is therefore first and non-negotiable.

## Required outcome

After this spec, there is one unambiguous Maximal Template architecture contract and no active governance may claim any of the following stale rules:

- static public pages are "marketing";
- public static pages require feature wrappers;
- no feature may ever import UI primitives;
- admin may live in a route group that removes `/admin` from the URL;
- form UI belongs in reusable blocks;
- the public demo must authenticate before it can be inspected.

## Canonical corrections

### Public versus marketing

`app/(public)` owns static public content.

`marketing` is the marketing automation/analytics business domain.

Static public routes with no application I/O compose blocks directly in `page.tsx`.

### Presentation contract

Normal flow:

```text
components/ui → components/blocks → features → app
```

Explicit exception:

```text
React Hook Form feature → components/ui
```

Form features do not require form blocks.

### Domain vocabulary

Use:

```text
crm
projects
support
marketing
invoicing
social
ai
portal
admin
user
common
```

### Library classifier

Enforce:

```text
persisted read        → lib/fetchers
CRUD persisted write → lib/actions
Prisma select         → lib/db/selects
DTO mapper            → lib/db/dto
transaction helper    → lib/db/transactions
Clerk/auth            → lib/auth
RBAC/ABAC             → lib/authz
provider behavior     → lib/integrations/{provider}
webhook HTTP          → app/api/{provider}/.../route.ts
remaining domain logic→ lib/workflows/{domain}
```

## Acceptance criteria

- [ ] No active governance calls static public routes "marketing routes/features".
- [ ] `marketing` is defined only as the marketing automation/analytics business domain.
- [ ] Static public pages are explicitly allowed to import blocks directly.
- [ ] Normal features compose blocks.
- [ ] RHF form features are explicitly allowed and expected to import UI primitives directly.
- [ ] Blocks are pure UI and may not own form state/provider/auth/database/business logic.
- [ ] Domain vocabulary exactly matches the canonical list.
- [ ] Action/fetcher/db/auth/authz/integration/workflow/webhook responsibilities are unambiguous.
- [ ] Public browseability and protected mutation permission are explicitly separate.
- [ ] Machine contracts match the human docs.
- [ ] Execution JSON does not claim unexecuted validation.
- [ ] Stale contradictory governance is deleted or clearly superseded.
- [ ] YAML and JSON parse successfully.
