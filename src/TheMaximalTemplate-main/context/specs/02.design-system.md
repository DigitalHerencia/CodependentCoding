# Spec 02 — Make the Design System Dark-Only and Mature Neo-Brutalist

**Priority:** P2  
**Depends on:** Spec 01

## Problem

The current production design defaults to a light cream palette with bright yellow, pink, cyan, and green accents.

The visual result is too playful/cartoonish for the intended Maximal Template identity.

Dark mode is currently treated as optional rather than canonical.

## Required outcome

Make dark mode the actual token system and normalize the UI primitive layer so all later blocks/features inherit the intended visual language.

## Visual target

The application should feel:

- near-black / charcoal;
- off-white;
- hard-edged;
- technical;
- dense;
- deliberate;
- mature;
- neo-brutalist without looking like a toy.

Use a restrained one- or two-accent palette.

## Root requirements

Update:

- `app/globals.css`;
- `app/layout.tsx`;
- any root theme/provider behavior;
- primitive variants that still encode the old palette.

The root document must render in the canonical dark system without requiring a user preference toggle.

## Token requirements

Define semantic tokens for:

- page background;
- surfaces;
- elevated surface;
- foreground;
- muted foreground;
- border;
- strong border;
- primary accent;
- secondary accent;
- success;
- warning;
- danger;
- info;
- focus ring;
- hard shadow;
- radius;
- motion.

Avoid component-level arbitrary palette literals where a semantic token exists.

## Primitive audit

Audit `components/ui/*` one primitive at a time.

For each active primitive verify:

- background;
- foreground;
- border;
- radius;
- shadow;
- hover;
- active;
- focus-visible;
- disabled;
- density;
- typography;
- keyboard behavior where relevant.

Do not restyle every feature individually to compensate for broken primitives.

## Geometry

Prefer:

- square or minimally rounded surfaces;
- strong borders;
- restrained hard shadows;
- clear layout grids;
- compact spacing.

Avoid excessive pill/card softness.

## Motion

Motion should be short and mechanical.

Avoid bouncy/springy default interactions.

Honor reduced-motion preferences.

## Public-page positioning

Remove generic conversion-funnel emphasis where it dominates.

Primary public calls to action should lead into exploration such as:

- dashboard;
- CRM;
- admin demo;
- features;
- component/block catalog;
- integrations.

Sign-up/sign-in remain secondary capability examples.

## Accessibility

Preserve:

- visible focus;
- keyboard navigation;
- semantic controls;
- sufficient contrast;
- touch usability;
- reduced motion.

## Acceptance criteria

- [ ] The application is dark-only by design.
- [ ] Root tokens no longer define the old cream/candy palette as default.
- [ ] Primary public routes render dark without a theme toggle.
- [ ] UI primitives use the canonical semantic token system.
- [ ] Accent usage is restrained.
- [ ] Neo-brutalist borders/shadows/geometry are consistent.
- [ ] Motion is controlled rather than playful.
- [ ] Focus and contrast remain accessible.
- [ ] Public positioning emphasizes exploration over account creation.
- [ ] No feature-specific CSS patchwork is used to compensate for primitive inconsistency.
