# Contributing

Choose a JSON specification from `context/specs/catalog.json`. Confirm its milestone, phase, dev cycle and documentation IDs; fill scope/acceptance/validation before execution. Publish one GitHub Issue per spec using `feature.yml` or `bug.yml`, or the dry-run-first CLI scripts. Use an issue-linked PR with the repository template, report only executed checks, and update the three `.agents/execution/` files with real evidence. Preserve unrelated work and current repository conventions. All production or irreversible operations require human approval.
