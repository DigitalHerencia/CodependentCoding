# Five documentation templates

| Document | Trace prefix | Primary responsibility |
|---|---|---|
| [PRD](PRD.md) | `PRD-` | Product scope, use cases, success |
| [Tech requirements](tech-requirements.md) | `TECH-` | Runtime, tools, nonfunctional needs |
| [Architecture](Architecture.md) | `ARCH-` | Boundaries and data flow |
| [Auth](AUTH.md) | `AUTH-` | Identity, roles, tenancy, access |
| [Design](Design.md) | `DES-` | UX, components, interaction, accessibility |

**Every file has exactly 100 individually identified authoring slots**, one per Engineering specification. An item may legitimately be `not_applicable` after the author records why. Do not fabricate requirements merely to fill a slot. Existing approved PRD and doctrine must be reconciled before these templates replace them.
