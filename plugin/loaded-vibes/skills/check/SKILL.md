# /check: run the profiles, fix by rule, rerun

Run inside an app generated by `hipster-stack new` (`hipster.json` at the root). The profiles are the app's own, in `.claude/contracts/validation.yaml`:

| Profile    | When                                | Commands                                           |
| ---------- | ----------------------------------- | -------------------------------------------------- |
| `quick`    | before a commit                     | `pnpm format:check`, `pnpm lint`, `pnpm typecheck` |
| `full`     | before a PR (default for `/check`)  | `pnpm validate`, `pnpm test`, `pnpm build`         |
| `security` | schema, RLS, auth or action changes | `pnpm test:rls`                                    |

Pick `full`, plus `security` when the diff touches `prisma/`, `lib/auth*`, `lib/authz`, `lib/actions` or `lib/db`. Use `quick` only when the owner asks for it. Read the profiles from the contract each time: an app may have added commands or `app_checks`.

## 1. Run

Run each command in order and keep its exit code and the last lines of output. `pnpm build` needs the env from `.env.local`; when a required variable is missing, record the check as `BLOCKED` with the variable's name (never its value) and go on with the rest. `pnpm test:rls` needs `DATABASE_URL_TEST`; without it the check is `NOT_RUN`, never "passed".

## 2. Group the lint findings

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/lint-findings.mjs" .
```

It runs the app's ESLint once and prints the findings grouped by rule, largest group first: `CC-*` doctrine IDs from the message prefix, other rules by their ESLint id. Look each CC ID up in `${CLAUDE_PLUGIN_ROOT}/references/doctrine.md` (rule table) before touching code.

## 3. Fix one rule at a time

- Fix the cause the rule names: move the code to its layer (`/loaded-vibes:classify`), add the missing `"use server"`/`server-only`, route the write through an action, rename to the layer's file pattern.
- Never add `eslint-disable`, never change `eslint.config.mjs`, `eslint/` or `validation.yaml` to get green, and never skip or delete a test. If a rule seems wrong for the case, stop and ask the owner; a doctrine change is its own decision.
- Format with `pnpm format` after edits. Typecheck errors and failing tests are fixed in the code under test, not the test, unless the test pins behaviour the issue changes.

After each rule's group, rerun the lint script; after all groups, rerun the whole profile. Stop after three full rounds that still fail and report what is left with its rule ID.

## 4. Record

Add each command to `.claude/execution/progress.json` as evidence:

```json
{
  "date": "<YYYY-MM-DD>",
  "state": "EXECUTED",
  "command": "pnpm validate",
  "result": "exit 0"
}
```

Use `NOT_RUN` or `BLOCKED` with the reason for anything not run. Then run `/loaded-vibes:handoff` if the session is ending.

## Record format

Write `.claude/execution/progress.json` only in the shape its `format` field spells out: statuses `todo`, `in-progress`, `in-review`, `done`, `blocked`; issue entries under `issues.<ID>`; one `evidence` entry per command, `{ "date", "state", "command", "result" }`, with `state` one of `EXECUTED`, `INSPECTED`, `NOT_RUN`, `BLOCKED`. Never add other top-level keys. Before handing back, run:

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/execution-check.mjs" .
```

Fix until it exits 0.

## 5. Hand back

One line per command (`pnpm lint: exit 0`), the rule groups fixed with their counts, the files changed, and anything `NOT_RUN` or `BLOCKED` with why.
