# /ship: env sync, deploy, smoke, evidence

Run inside an app generated by `hipster-stack new` (`hipster.json` at the root). A production deploy changes a live service: run steps 3 and 4 only after the owner says to ship in this conversation. Everything before them is safe to run any time.

## 1. Preconditions

- `/loaded-vibes:check` (full profile) is green on this commit, and `git status` is clean. Deploy what is committed.
- The Vercel CLI works and the app is linked: `vercel whoami` exits 0 and `.vercel/project.json` exists. If it is not linked, stop and ask: linking creates or reuses a Vercel project (`hipster-stack new . --provision` does it for apps made with the CLI).
- The database exists and is migrated: `pnpm db:init` has run against the production `DATABASE_URL` (the owner runs it or says to).

## 2. Plan the env sync (dry run)

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/ship-env.mjs" .
```

It reads `.env.example` (names, required or optional) and `.env.local` (which names have a value) and prints three lists, names only: pushed to production, kept local because they are test-only (`*_TEST*`), and optional but unset. It exits 1 when a required name has no value; stop and ask the owner to fill it. Never print, echo or paste a value; never read `.env.local` yourself.

Show the owner the push list and ask to ship.

## 3. Sync and deploy (owner approved)

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/ship-env.mjs" . --apply
vercel deploy --prod --yes
```

`--apply` runs `vercel env add <NAME> --environment production --sensitive --force --yes` per name with the value on stdin. `vercel deploy --prod` prints the deployment URL on its last line; keep it. If the build fails, read `vercel inspect <url> --logs`, fix locally, rerun `/check`, commit, and deploy again.

## 4. Smoke the URL

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/smoke.mjs" <url>
```

Two checks, the same as `tests/e2e/smoke.spec.ts`: `/` returns 200 with an `<h1>`, and `/dashboard` redirects a signed-out visitor to `/sign-in`. A failure is a failed ship: report it, never call the deploy done.

## 5. Record

- `progress.json` evidence: one entry per command above (`vercel deploy --prod` with the URL as the result, and each smoke check).
- `decisions.json`: a decision when you changed an env name, the project, or the domain.
- `handoff.json`: the production URL in `notes`, and any check that was `NOT_RUN`.

## 6. Hand back

The URL, the smoke results, the env names pushed (names only), and what was not run.
