# /handoff: record what happened, point at what is next

Run inside an app generated by `hipster-stack new` (`hipster.json` at the root). The files are in `.claude/execution/`; each has a `format` field, and `progress.json`'s spells out the one record shape every skill writes. Write only facts from this session: a command you ran and its result, a choice you made, the state of the branch.

## 1. Gather

- `git status`, `git log --oneline origin/main..HEAD` (or the last commits), the current branch and open PR.
- The issue being worked (`handoff.json` `current_issue`/`next_issue`) and its file in `context/specs/issues/`.
- The commands run this session and their exit codes. A command you did not run is `NOT_RUN`; never write that it passed.

## 2. progress.json

Under `issues.<ID>`: `status` (`todo`, `in-progress`, `in-review`, `done`, `blocked`), `branch`, `pr` when there is one, `decision` ids, and `acceptance` with one line per acceptance criterion, each starting with its evidence state:

```json
"acceptance": {
  "Visits list renders for a crew lead": "EXECUTED: pnpm test tests/field/visits.test.ts -> 6 passed",
  "Cross-tenant reads fail": "NOT_RUN: DATABASE_URL_TEST not set"
}
```

Append each command to `evidence` as `{ "date", "state", "command", "result" }`. `in-review` and `done` need at least one `EXECUTED` line. Set the issue file's `status` front matter to match.

## 3. decisions.json

Append, never edit or renumber: `{ "id": "DEC-NNN", "date", "status": "accepted" | "proposed", "title", "context", "decision", "refs" }`, the next number after the last entry. A choice the owner has not confirmed is `proposed`. Record interpretations of the PRD or doctrine, names you picked, and anything deferred.

## 4. handoff.json

Overwrite: `updated` (now, ISO), `status`, `current_issue`, `next_issue` (the first issue whose `depends_on` are done), `queue` (the rest in dependency order), `branch`, `in_flight` (open PRs), `notes` (what the next session must know, one line each), `risks`, `do_not`.

## 5. Check

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/execution-check.mjs" .
pnpm format
```

The check exits 1 when a file does not parse or lost its `$schema`, a decision id is out of order, an issue id in handoff or progress has no file, an acceptance line has no evidence state, or an `in-review`/`done` issue has no `EXECUTED` line. Fix until it exits 0.

## 6. Hand back

The issue and its status, the decisions added, the next issue, and anything `NOT_RUN` or `BLOCKED`.
