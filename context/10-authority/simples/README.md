# Simples™ Authority Package

This package establishes the canonical definition:

```text
SIMPLES™
=
PureUI Blocks™ Presentation Layer
+
BusinessLogic Blocks™ Domain Workflows
```

## Files

1. `10.PROJECTS.CODEPENDENTCODING.Simples.Authoritative-Source-Spec.md`
   - authoritative two-family definition
   - PureUI constitution
   - BusinessLogic constitution
   - constituent-vs-Simple distinction
   - Anthimeria / Ontology / Virgule / Arrangement relationships
   - compatibility and dependency rules
   - Codex rules

2. `10.PROJECTS.CODEPENDENTCODING.Simples.Canonical-Catalog.md`
   - source-backed Component Block inventory
   - UI Primitive constituent inventory
   - named shared presentation inventory
   - Semantic Design Tokens
   - all canonical Workflow files
   - lower-level BusinessLogic constituent inventory

3. `10.PROJECTS.CODEPENDENTCODING.Simples.Generic-Reference-Implementation.md`
   - generic PureUI Block
   - generic BusinessLogic Block
   - Feature using both
   - variants
   - Primitive substitution
   - token example
   - anti-patterns and acceptance checks

## Canonical correction

Routes, Features, Primitives, Actions, Fetchers, Schemas, Types, Integrations, Shells, Templates, and other architecture-owned artifacts may be constituents or orchestration boundaries, but they are **not themselves top-level Simples™** under this package.
