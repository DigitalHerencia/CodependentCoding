# Routing and Rendering

## Route groups

| Group      | Purpose                                        | Shell          | Auth             | Rendering                                                  |
| ---------- | ---------------------------------------------- | -------------- | ---------------- | ---------------------------------------------------------- |
| `(public)` | landing, pricing, FAQ, terms, privacy          | `public-shell` | none             | static (`ensureStatic = 'navigation'` on the group layout) |
| `(auth)`   | sign-in, sign-up, onboarding, pending approval | `auth-shell`   | Clerk components | dynamic                                                    |
| `(tenant)` | the product, one folder per slice              | `tenant-shell` | required         | dynamic, streamed                                          |
| `(admin)`  | operator console                               | `admin-shell`  | admin role + MFA | dynamic, streamed                                          |

Route-group names never appear in the URL, so no two groups may define the same path. Each group has its own `layout.tsx`, `loading.tsx` and `error.tsx`. The app root has `global-error.tsx` and `not-found.tsx`. `error.tsx` and `global-error.tsx` are client components.

## The slice route pattern

```text
app/(tenant)/crm/contacts/page.tsx                 list   (data table + filters from searchParams)
app/(tenant)/crm/contacts/new/page.tsx             create (form)
app/(tenant)/crm/contacts/[contactId]/page.tsx     detail
app/(tenant)/crm/contacts/[contactId]/edit/page.tsx edit  (form)
```

Dynamic segment names are `<entity>Id`, never bare `[id]`, so nested segments stay unambiguous and typed routes read clearly.

## Thin routes

> **CC-ROUTE-001** · `now` · `codependent/layer-boundaries`
> A route imports one feature (or, in `(public)`, blocks), its skeleton, and nothing from `lib/` except `lib/auth/redirects`.

```tsx
// app/(tenant)/crm/contacts/[contactId]/page.tsx
import { Suspense } from "react";
import { CrmContactFeature } from "@/features/crm/crmContactFeature";
import { CrmContactSkeleton } from "@/features/crm/crmContactSkeleton";

export default async function Page({
  params,
}: PageProps<"/crm/contacts/[contactId]">) {
  const { contactId } = await params;
  return (
    <Suspense fallback={<CrmContactSkeleton />}>
      <CrmContactFeature contactId={contactId} />
    </Suspense>
  );
}
```

`params` and `searchParams` are Promises in Next 16. The route does not validate them; the fetcher does (it is the trust boundary that uses them). `PageProps<…>` is the typed-routes helper generated by `next typegen`.

> **CC-ROUTE-002** · `now` · `codependent/layer-boundaries`
> `proxy.ts` only gates: Clerk session presence, the CSP nonce, and redirects. It never reads the database and is never the enforcement point.
> The proxy sees a URL, not a resource: it cannot know which record an action will touch or which permission it needs, matchers drift as routes are added, and the 2025 middleware-bypass advisory (CVE-2025-29927) showed the front door can be skipped entirely. Layouts do not re-run on client navigation within their segment. Enforcement is in the data layer.

> **CC-ROUTE-003** · `now` · review
> Layout-level checks (onboarding complete, pending approval, admin role) are UX. Every fetcher and action re-checks.

> **CC-ROUTE-004** · `now` · `codependent/no-dynamic-params-export`
> No `dynamic`, `revalidate`, `fetchCache` or `dynamicParams` segment exports. Unknown params resolve to `notFound()` in the feature.
> These are build errors under Cache Components.

## Suspense and loading

- Every feature that awaits data renders behind `<Suspense>` with a skeleton that mirrors the final layout (same grid, same block heights). Spinners are for actions, not page loads.
- `loading.tsx` is the coarse fallback for a whole group and appears only on the first navigation into it.
- Independent reads in one feature start together (`Promise.all`) or live in sibling Suspense boundaries so the slowest does not block the rest.
- `useEffect` is never used to fetch data.

## The caching model

Cache Components is on (`cacheComponents: true`, `partialPrefetching: true`). Nothing is cached unless code says so. A route is a mix of three things:

| Kind    | How it is declared                                                                  | Example                                                |
| ------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Static  | no request data, no `await` of dynamic APIs                                         | marketing copy, docs                                   |
| Cached  | `'use cache'` + `cacheLife(...)` + `cacheTag(...)` on a function or component       | public pricing table, published knowledge-base article |
| Dynamic | reads `cookies()`, `headers()`, `auth()`, `params` at request time, inside Suspense | everything in `(tenant)` and `(admin)`                 |

> **CC-CACHE-001** · `now` · `codependent/layer-boundaries`
> `lib/cache` holds tag builders, lifetime profiles and invalidation helpers only. It imports no data layer.

> **CC-CACHE-002** · `now` · `codependent/no-cache-in-protected`
> `'use cache'` MUST NOT appear in `features/` or `lib/fetchers/` of any slice reachable from `(tenant)` or `(admin)`, nor in any function that receives an identity, membership or organization ID.
> A shared cache entry keyed by arguments cannot express "and only this user may see it". One missed argument leaks one tenant's data to another.

> **CC-CACHE-003** · `now` · review
> Authorization, membership, payment and readiness decisions are never read from a cache.

> **CC-CACHE-004** · `now` · `codependent/cache-tag-builders`
> Tags are built only by `lib/cache/tags.ts` functions; no inline string tags.

```ts
// lib/cache/tags.ts
export const tags = {
  publicPricing: () => "public:pricing",
  kbArticle: (slug: string) => `public:kb:${slug}`,
} as const;

// lib/cache/life.ts — named profiles, one place
export const life = { marketing: "days", catalog: "hours" } as const;

// lib/cache/invalidate.ts
import "server-only";
import { revalidateTag } from "next/cache";
import { tags } from "./tags";
export function invalidateKbArticle(slug: string) {
  revalidateTag(tags.kbArticle(slug), "max");
}
```

Tenant pages are fresh on every request. After a mutation the action invalidates the paths or tags it touched; because tenant data is not in a shared cache, invalidation there only refreshes the client router cache.

## Static guarantee

The `(public)` group layout exports `ensureStatic = 'navigation'`. If a dynamic component ever enters a public page, the build fails. A marketing site that silently became server-rendered is a cost and an attack-surface regression nobody notices until the bill.

## Prefetching

`<Link>` prefetches cached UI by default. For lists of links to expensive detail pages, the detail feature awaits `navigation()` (from `next/cache`) before the expensive part, so prefetch loads the header and a navigation loads the rest.

## File conventions per group

```text
app/(tenant)/layout.tsx     shell + UX redirects (onboarding, pending, suspended)
app/(tenant)/loading.tsx    shell-shaped skeleton
app/(tenant)/error.tsx      "use client"; reset button; reports to observability
app/global-error.tsx        "use client"; own <html>/<body>
app/not-found.tsx           static
```

Error boundaries catch render errors only. Action failures arrive as `ActionResult` values, never as thrown errors on the client.
