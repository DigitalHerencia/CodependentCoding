# Chapter 17: Governance System

**The Book of Knowledge™**

## Definition

- Governance preserves durable intent, authority, decisions, exceptions, and evidence so implementation can change without silently changing what the system means. Governance is useful only when it improves intent, implementation, evidence, or outcome.

## Authority order

- Current human instruction.
- Canonical doctrine/architecture/security/lifecycles.
- Accepted decisions and scoped specifications.
- Deterministic machine contracts.
- Implementation and tests as evidence.
- Mutable execution state.

## Change control

- Classify the change and owner. Inspect governing sources and affected implementation. Resolve contradictions before implementation. Approve only the amount of specification proportional to the change. Implement the smallest correct change. Execute required evidence. Update durable owners when public boundaries change.

## Anti-ceremony

- Do not create manifests, validators, reports, or execution artifacts merely to prove that governance artifacts exist. Assurance terminates at meaningful evidence.
- Technical debt is an owned observable inconsistency, not a euphemism for unresolved architecture.
