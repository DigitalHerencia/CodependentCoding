# LV-105 — Product identity and design personalization

## Outcome

Generated applications should feel like the user's product before domain feature work starts.

## Scope

- add bounded design recipe fields for theme preset, mode, radius, density, navigation shell, and product identity;
- map design choices through semantic tokens/known template surfaces;
- personalize safe product copy/metadata surfaces;
- provide several polished built-in visual presets including the dark `obsidian` direction.

## Acceptance

- changing a supported design choice produces a coherent visible change in generated output;
- personalization uses targeted transforms, not blind global replacement;
- product identity does not rename domain/security/provider concepts;
- defaults remain visually polished without user customization.
